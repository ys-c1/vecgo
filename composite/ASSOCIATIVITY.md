# 半透明图层合成与结合律

记号：图层用像素 `(C, a)` 表示，`C` 为颜色、`a ∈ [0,1]` 为不透明度。
Porter-Duff 的 "over"（上 `t` 盖下 `b`）在**预乘 alpha** 空间写成
（`e = a·C` 为预乘颜色能量）：

```
e_o = e_t + (1-a_t)·e_b                         (1)
a_o = a_t + (1-a_t)·a_b                         (2)
```

## 1. 预乘 alpha 下 over 满足结合律

要证 `(A over B) over C = A over (B over C)`。`e`、`a` 两通道结构完全相同，
只需证一个通道；把 (1)(2) 统一写成二元运算 `x*y = x_t + (1-x_t)·x_b`。

先展开左边 `L = (A*B)*C`：

```
A*B        = A + (1-A)·B
L          = [A + (1-A)·B] + (1-[A + (1-A)·B])·C
           = A + (1-A)·B + (1-A)·(1-B)·C
```

再展开右边 `R = A*(B*C)`：

```
B*C        = B + (1-B)·C
R          = A + (1-A)·[B + (1-B)·C]
           = A + (1-A)·B + (1-A)·(1-B)·C
```

`L = R`，证毕。对 alpha 通道代入 (2)、对每个颜色通道的能量代入 (1) 同时成立，
所以三通道整体结合。等价地，任意 n 层合成与括号无关地展开为同一条幂次和：

```
a_out = Σ_k a_k · ∏_{j>k}(1-a_j)
e_out = Σ_k e_k · ∏_{j>k}(1-a_j)              (3)
```

这正是 `Composite` 里累加器直接求值的式子：每层只贡献一次，没有中间除法。

注意：结合律不等于交换律。`A over B` 与 `B over A` 一般不同（图层上下次序
有物理意义）；结合律保证的是**同一图层次序下，先叠哪两张不影响结果**。

## 2. 非预乘（straight alpha）下结合律为何在实现中失效

straight 表示每步都要把预乘能量除回颜色 `C = e/a`：

```
C_o = (a_t·C_t + (1-a_t)·a_b·C_b) / a_o        (4)
```

在**精确实数算术**下，(4) 只是 (1) 的代数变形，数学上仍然结合
（仓库 `scratch/` 里的 Fraction 对拍可验证：精确解差异恒为 0）。
但任何 8-bit 实现都必须在每一对合成后把 `C_o`、`a_o` 舍入回 0..255，
于是下一步拿到的是被量化过的 `a_o` 与 `C_o`。设量化算子为 `Q`：

```
左括号: Q( Q(Q(A over B)) over C )
右括号: Q( A over Q(Q(B over C)) )
```

两次量化插入的位置不同。`Q` 是单调多对一映射、与 over 不可交换，
两个表达式不再恒等——这就是实测中逐像素差异的来源。**根因不是
"straight 这个数学公式不结合"，而是 straight 管线强迫在中间步骤量化**；
预乘管线可以把量化推迟到全部折叠完成之后，从而保住结合律。

## 3. 反例（8-bit，单通道即可复算，坐标见 composite_test.go）

以 alpha 组 `(a_A,a_B,a_C) = (80,160,120)`、像素 `(C_A,C_B,C_C)=(0,0,3)`
为例（数值均为 0..255 的整数，四舍五入）：

左括号 `(A over B) over C`：

```
A over B: a = (80·255 + 175·160)/255 = 220
         e = (0·255 + 175·0)/255 = 0,  C = 0
再 over C: a = (220·255 + 35·120)/255 = 220
          e = (0·255 + 35·(3·120)/255)/255 ≈ 1.96 → C = round(1.96/220·255) = 0
```

右括号 `A over (B over C)`：

```
B over C: a = (160·255 + 95·120)/255 = 205
         e = (0·255 + 95·360)/255 = 134,  C = round(134/205) = 1
再 over A: a = (80·255 + 175·205)/255 = 220
          e = 0 + 175·(1·205)/255/255 ≈ 0.55
          C = round(0.55/220·255) = 1
```

左括号得 `C=0`，右括号得 `C=1`，同一张图差 1 个色阶。
三组透明度下的全空间（256³ 种颜色组合）统计与三个反例点坐标由
`go test ./composite/ -v` 输出。

## 4. 按结合律重写后的合成

`Composite` 不再逐层 `over` 并回写 8-bit 缓冲，而是对每个像素在预乘空间
按 (3) 式让每层只贡献一次，最后做**唯一一次**除回与半值向上舍入。
实现为双路径：

- **快速路径**：`float64` 预乘累加器。float64 加法本身不结合，全空间扫描
  显示纯 float64 累加器在约 0.24% 的颜色组合上有 1 色阶差异，不能单独使用；
- **精确回退路径**：当某通道结果落在舍入半值的 `1e-6` 邻域内（浮点结合误差
  可能翻转整数结果）时，该像素改用 `math/big` 约分分数累加，得到精确结果。

1139 万组颜色/alpha 组合对拍（`TestDualPathMatchesExact`）证明双路径输出与
纯精确路径逐像素一致；基准测试中 256×256×3 合成约 1.7 ms（纯 big.Int 约
581 ms）。由于求值的就是与括号无关的闭式幂次和且生产输出与精确路径恒等，
左括号、右括号（以及任意 n 层的任意结合方式）输出逐像素相同。

## 5. 实测数据

全空间扫描：固定每组 alpha，枚举全部 256³ = 16,777,216 种颜色三元组，
比较 `((A over B) over C)` 与 `(A over (B over C))` 的 8-bit 输出
（脚本 `scratch/search4.py`，与 Go 实现同构）。

**第一段：三条管线在三组透明度下的差异像素数（全空间 16,777,216 点）**

| alpha (A,B,C) | 朴素 straight 逐步量化 | 预乘但逐步量化 | 精确有理数累加器（本实现） |
|---|---|---|---|
| (80,160,120)  | 5,441,744 | 5,344,256 | **0** |
| (40,200,100)  | 5,354,124 | 5,559,808 | **0** |
| (120,90,170)  | 5,095,527 | 5,752,576 | **0** |

两条逐步量化管线各有约 30–34% 的像素不结合；精确累加器三组全部为 0。
注意"预乘但逐步量化"同样大量失败——预乘只是必要条件，消除中间量化才是
结合律成立的关键。
