# 填充覆盖率统计

用于排查「斑驳的接缝」：怀疑同一像素被多个图形反复填充。统计会记录
每个像素被多少个图形写入，按覆盖次数分 1 / 2 / 3+ 三档统计像素数，把
覆盖总次数与图形面积和作差，并列出覆盖次数最高的 10 个像素及覆盖它们
的图形。

## 用法

```sh
# 只渲染（统计关闭，产物与旧版本逐字节相同）
go run ./cmd -scene seam -o out.pgm

# 开启统计：标准输出打印报告
go run ./cmd -scene seam -coverage -o out.pgm

# 同时把分桶表导出为 CSV（隐含开启统计）
go run ./cmd -scene seam -coverage-csv buckets.csv -o out.pgm
```

场景：

| `-scene`  | 内容 | 预期 |
|-----------|------|------|
| `square`  | 单个正方形 | 全部 1 次，差值 0 |
| `seam`    | 正方形沿对角线拆成两个三角形 | 接缝对角线像素被两个图形覆盖 |
| `overlap` | 两个 8×8 正方形错开 4 | 重叠 4×4 区被两个图形覆盖 |
| `stack`   | 四个 8×8 正方形错开 3 | 中心区被三到四个图形覆盖 |

## 计数口径

- 某图形只要有任意一个子采样点落在像素内，就把该像素记一次；
- 同一图形的多个子采样点不重复计，不同图形各记一次；
- 因此「覆盖次数」= 覆盖该像素的图形个数。它量化的是多图形叠加，
  而不是内存写操作次数——`Fill` 对每个像素只做一次最终赋值。

## 实测数字（64×64，超采样 2×2）

| 场景 | 覆盖总次数 | 面积和 | 差值 | 1 次 | 2 次 | 3+ |
|------|-----------|--------|------|------|------|-----|
| `square`  | 4096 | 4096.000  | +0.000    | 4096 | 0    | 0   |
| `seam`    | 4160 | 4096.000  | +64.000   | 4032 | 64   | 0   |
| `overlap` | 3698 | 3640.889  | +57.111   | 2730 | 484  | 0   |
| `stack`   | 8836 | 8665.917  | +170.083  | 1156 | 2040 | 900 |

`stack` 覆盖次数最高的 10 个像素均落在中心区，次数 4，由 `#0`、`#1`、
`#2`、`#3` 四个正方形叠加；`seam` 的 10 个最高像素沿对角线，次数 2，
由 `#0`、`#1` 两个三角形叠加。

完整样例输出见 `docs/stack_report.txt` 与 `docs/stack_buckets.csv`。

## 报告字段

```
覆盖总次数 8836                              ← Σ 每个像素的覆盖次数
面积和（像素单位，重叠重复计）8665.917        ← Σ 每个图形的像素面积
差值（覆盖总次数 - 面积和）+170.083          ← 具体要求的具体数字
相对差值 +1.9627%
```

差值按图形分解：

```
差值 = Σ_图形 (该图形触及的像素数 - 该图形像素面积)
```

每个图形的贡献即它边界上半覆盖像素带来的缺口；报告「图形一览」里逐行
给出每个图形的面积、触及像素数与缺口，其和与上面的差值相等，可相互
核对。面积以像素为单位，x、y 方向分别按 `画幅/包围盒` 缩放，与填充
采样映射一致；重叠部分在面积和中重复计，因此互不重叠且恰好铺满时
差值为 0，接缝/重叠场景差值为正。

## 分桶表

报告文本中的分桶表与 CSV 都是两列：

```
次数区间,像素数
1,1156
2,2040
3+,900
```

`3+` 表示 3 次及以上。三档像素数之和等于「有覆盖像素」；把 1、2 档
的像素数分别乘以 1、2，3+ 档至少乘以 3，所得下界不应超过覆盖总次数
（3+ 档内像素次数可能更高，超出部分需逐像素核对）。

## 逐行复核

`CoverageStats.Verify` 检查以下等式，任一不成立即列出具体不符项：

1. `Σ Counts == TotalWrites`
2. 分桶像素数之和 == `CoveredPixels`，且不超过画幅像素数
3. 分桶 Writes 之和 == `TotalWrites`
4. `Hist` 各档像素数之和 == `CoveredPixels`
5. Top 像素的 `Count` 与 `Counts` 表一致，图形明细个数等于 `Count`
6. 逐图形面积之和 == `AreaSum`
7. 差值分解 `Σ(触及 - 面积)` == `Diff()`

测试中每个场景都会跑一遍 `Verify`，见 `raster/coverage_test.go` 与
`pipe/stats_test.go`。

## 产物不变

统计只读地观察填充过程，不改变写入 `Pix` 的字节。包含统计路径的测试
逐字节比较开/关统计的 PGM；默认调用（`-scene square`，无 `-coverage`）
的产物哈希与未加统计时相同：

```
fbda3e5665174433272beab4f25172bc03466e3f8700bcf6007b32c3636f2dc3
```

## API

- `raster.Image.Fill`：原接口，不变；
- `raster.Image.FillStats`：与 `Fill` 产物相同，返回 `*raster.CoverageStats`；
- `CoverageStats.Report(io.Writer)`：文本报告；
- `CoverageStats.WriteBucketCSV(io.Writer)`：两列分桶表；
- `CoverageStats.Verify() []string`：账目核对；
- `pipe.RunWithStats`：整条管线的统计版本，产物与 `pipe.Run` 相同。
