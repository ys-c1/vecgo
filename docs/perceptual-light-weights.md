# 多光源权重：按感知亮度守恒反解（非线性）

> 目标：两盏灯的线性强度直接相加会得到单灯两倍能量，朴素“线性归一”
> （把权重归一到和为 1，两灯各 `1/2`、取算术平均）又不符合感知叠加，
> 处理暗部时容易丢绝对尺度、显得发灰/发闷。这里改为**按感知亮度守恒**
> 求权重，使叠加后的感知亮度等于各单灯感知亮度之和，而**不是**让线性总能量
> 满足 `w1+w2=1` 之类的相等关系。单光源是该方程的平凡恒等特例，路径不变。

代码：`light/`（`brightness.go` 感知定义、`weights.go` 非线性求解、
`coverage.go` 覆盖率—位置）。复现：

```bash
go test -count=1 ./...
go run ./cmd/lightreport -out artifacts/light
```

## 1. 感知亮度的定义（先写清，不只给结论）

彩色线性光域先用 Rec.709/sRGB 系数求相对亮度

```
Y = 0.2126 R_lin + 0.7152 G_lin + 0.0722 B_lin。
```

本仓是灰度 PGM，`R=G=B=I`，故 `Y=I`，彩色系数退化为标量线性强度。
采用 CIE 1976 明度 `L*` 作为“感知亮度”的标准定义：

```
L*(Y) = 116 f(Y) - 16
f(t)  = t^(1/3),                                      t > ε
      = t / (3δ²) + 4/29 = (κ/116) t （故 L*=κY）,    t ≤ ε
δ = 6/29,  ε = δ³ = 216/24389 ≈ 0.00885645,  κ = 24389/27 ≈ 903.2963。
```

归一化感知亮度取

```
P(Y) = L*(Y)/100 ∈ [0,1]（参考白 Y=1 → P=1）。
```

线性趾保证 `Y=0 → L*=0`（黑仍是黑，不会被抬成灰），且 `L*` 与其一阶导数
在 `Y=ε` 处连续。逆函数（`light.InvPerceived`）：

```
L* ≤ 8  → Y = L*/κ；否则 Y = ((L*+16)/116)^3。
```

另有幂律/显示 gamma 口径 `P_γ(I)=I^(1/γ)`（典型 γ=2.2，闭式工作台 γ=2）
用于交叉核对；它和 `L*` 一样是线性光的**凹**函数。

**适用性**：`L*`/幂律描述中性灰、明视觉、稳态适应、同尺寸同空间频率色块的
明度；不直接覆盖彩色对立通道（该用 CIELAB/OKLab 色度距离）、暗视觉、
HDR 局部适应与空间效应。题目规定的“感知亮度可加”是一种**守恒准则/建模
约定**；真实视觉对同一点受多光的响应更接近“先在线性光累加 `S=ΣI`、再走
非线性 `P(S)`”，此时主观明度是 `L*(S)` 而非 `ΣL*(I_i)`。两者本文都列出，
验收对照按题目指定的 `ΣL*(I_i)` 守恒口径。

## 2. 权重推导：守恒方程是非线性的

设两灯线性强度为 `I1,I2`，和 `S=I1+I2`。一个标量方程不能唯一确定两个独立
权重（欠定），因此采用灯组整体增益/配平这一自然约定：各灯乘同一个守恒
权重 `w`（相对配比保持不变，`w1=w2=w`）。要求叠加后的感知亮度等于两灯
各自感知亮度之和：

```
P(w·(I1+I2)) = P(I1) + P(I2)。                         …(1)
```

这就是关于 `w` 的非线性方程（`P` 非线性）。令目标
`T = min(P(I1)+P(I2), 1)`（超过参考白时裁切到 1 并置 `Clipped`），由 `P`
可逆直接得闭式参考解：

```
w* = P^{-1}(T) / S。                                    …(2)
```

闭式解只用于交叉核对；主路径仍按要求做非线性迭代，以报告**迭代次数与残差**。

**为什么权重不是 1/2、且在暗部 >1。** 标准 `P` 凹且次可加：
`P(I1+I2) ≤ P(I1)+P(I2)`，所以原始线性相加 `w=1` 的感知亮度 `P(S)` 小于
“两份单灯感知之和”；要达到式 (1) 的目标，暗部组需要 `w*>1`（见第 4 节）。
幂律口径同理（G1 的 γ2.2 解为 `w=2.2974`）。这不是让能量翻倍更亮，而是
题目指定的感知可加准则在凹感知曲线上的数学结果。

**与“线性归一”的对立。** 朴素线性归一令 `w1+w2=1`，两灯即
`w_L=1/n=1/2`，线性输出 `V_L=S/n`，其亮度读数为 `L*(S/n)`。它守恒的是
“权重和/线性平均”，**不是**式 (1) 的感知和；本文不强制 `wS` 等于 `S`，
也不强制 `w1+w2=1`。线性比例权重 `a_i=I_i/S` 也一并在结果里给出
（`Result.WeightsProportional`），它是无绝对尺度的比例；若把比例本身当成
灰度渲染，暗灯会被错误抬到中灰——这正是“归一让暗部发灰”的来源之一。

## 3. 求解方法与收敛判据

定义残差

```
F(w) = P(wS) - T，
F'(w) = S · P'(wS)，
P'(Y) = L*'(Y)/100，
L*'(Y) = κ（Y≤ε）；116 / (3·cbrt(Y)²)（Y>ε）。
```

用**解析导数 Newton 迭代**，初值 `w0=1`：

```
w_{k+1} = w_k - F(w_k)/F'(w_k)。
```

Newton 可能在裁切/大强度情形越界，故加**二分区间保护**：维护
`[lo,hi]` 使 `F(lo)≤0≤F(hi)`（从 `[0,1]` 起倍增出 `hi`），每步按 `F(w)`
符号收窄区间；当 Newton 点不落在区间内或导数失效时，本步改取区间中点。
`P` 单调递增保证根唯一、区间保护使其对任意有限非负输入不发散。

**收敛判据（残差 + 相对步长双条件，同时满足）**：

```
|F(w_k)| ≤ ε_F = 1e-13，
|w_{k+1}-w_k| ≤ ε_w·(1+|w_k|)，ε_w = 1e-14（或步长在 float64 上已归零），
最多 K=50 轮；超限返回 Converged=false。
```

验收三组全程为纯 Newton 步（`Guarded=false`），**5–6 次**即到机器精度地板。

## 4. 三组强度：线性归一 vs 感知归一（两种亮度值并列）

亮度统一在同一把感知尺 **CIE L\***（0–100）上读数；括号里是归一化 `P`。

| 组 | `(I1,I2)` | 线性归一 `w_L` | 线性输出 `S/2` | **线性归一亮度 L\*** | 感知守恒 `w*` | 感知输出 `w*S` | **感知归一亮度 L\*** | 目标 `ΣL*` |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| G1 等高暗调 | `(.10,.10)` | .5 | .100 | **37.8424** (P=.378424305) | 2.468817166 | .493763433 | **75.6849** (P=.756848609) | 75.6849 |
| G2 强主弱辅 3:1 | `(.18,.06)` | .5 | .120 | **41.2161** (P=.412161201) | 2.282081294 | .547699511 | **78.9086** (P=.789085722) | 78.9086 |
| G3 深暗跨线性趾 | `(.012,.004)` | .5 | .008 | **7.2264** (P=.072263704) | 1.099653786 | .017594461 | **14.1706** (P=.141705556) | 14.1706 |

解读：

- G1 两灯相同，线性归一取平均后亮度恰好等于单灯 `L*(.1)=37.84`；感知守恒
  要的是“两份 37.84 之和” `75.68`，两者差一倍的感知目标。
- G3 的线性归一输出 `.008 ≤ ε`，落进 L\* 线性趾，故
  `L*=κ·.008=7.2264`；其中 `.004` 那盏本身也在线性趾
  `L*(.004)=3.6132`。
- 原始线性相加（不归一，`w=1`）的感知亮度分别只有
  `L*(.2)=51.8372`、`L*(.24)=56.0878`、`L*(.016)=13.2302`，
  均低于感知和 `75.68/78.91/14.17`——凹曲线使“两倍能量”并不等于“两倍
  主观明度”。等高 G1 的线性和 `.2=2×.1`，正是题述“亮两倍能量”。

G2=2.282 而 G3=1.100——选用哪种感知定义会影响暗部权重，需按显示链路取舍。

## 5. 覆盖率—位置函数：两三个点

与 `raster.Image.Fill` 的面积/中点采样口径一致。单位像素 `[0,1]` 被直边
`x=c`（保留 `x≤c`）覆盖的覆盖率闭式为

```
C(c) = clamp(c, 0, 1)。
```

题目只要两三个点，取内部三点：

| 位置 `x=c` | **覆盖率 `C(x)`** | 本仓截断灰度 `uint8(255C)` |
|---:|---:|---:|
| 0.25 | **0.25** | 63 |
| 0.50 | **0.50** | 127 |
| 0.75 | **0.75** | 191 |

整数位置核对：`C(0)=0`、`C(1)=1`（整数位置只取 0/1，无中间灰）。
与 **16×16 中点超采样**（采样公式同 `Fill`）对照，三点分别命中
`64/256、128/256、192/256`，覆盖率 `.25/.5/.75`，与闭式**绝对差 0**。
注意本仓灰度是整数截断：`C=.5 → uint8(127.5)=127`，不是四舍五入的 128。

把权重乘到覆盖率/位置上（共享同一边覆盖率）：`E(x)=w·C(x)·S`。以 G1 为例，
`x=.25/.5/.75` 时 `E=.123441/.246882/.370323`，对应
`L*(E)=41.7578/56.7703/67.3012`；`C=1` 回到第 4 节守恒输出，`C=0` 为全黑。

## 6. 单光源路径不变（逐值 + 字节双锁定）

- API 层：`light.Compare` 对 `n==1` 直接返回 `Weight=1、Out=I[0]`
  （用精确 `Out != I` 断言，要求 bit 级不变）、`Iterations=0、Residual=0`、
  `Solver="single-light-identity"`，不构造方程、不缩放；强度为 0 的单灯
  也走同一恒等分支。`n==0`/多灯全 0 给确定全零结果；负/NaN/±Inf 强度报错。
- 产物层：没有改动任何既有渲染文件，默认 `pipe.Run` 仍走原
  `shading.Apply → Gamma(1) → Blur(0)`。`pipe.TestDefaultArtifactByteIdentical`
  锁定落盘 PGM 的完整 sha256：

| 产物 | sha256 |
|---|---|
| 默认 flat64（stdout `on=4096 size=64x64`） | `fbda3e5665174433272beab4f25172bc03466e3f8700bcf6007b32c3636f2dc3` |
| gradient64 | `b31af655f7ee15cb9cc4133a6d4e95ad69b8b9c0fd1e82d9728278189b4224a7` |
| gradient256 | `005f598269f05555e7b788edc07e6bec4375a9e2a1b1046cf95886c692a742a7` |
