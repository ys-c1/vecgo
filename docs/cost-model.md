# vecgo 渲染管道：代价模型与阶段计时对照

## 1. 五个阶段（按 `pipe.Run` 执行顺序）

| 顺序 | 阶段 | 代码位置 | 主要工作 |
|---|---|---|---|
| 1 | `transform` | `pipe.Transform` | 逐顶点仿射变换（缩放/旋转） |
| 2 | `rasterize` | `raster.Image.Fill` | 每像素超采样 + 多边形内外判定 |
| 3 | `shading` | `shading.Apply` | 非零像素写入着色值 |
| 4 | `gamma` | `post.Gamma` | 256 项查找表 + 整图查表 |
| 5 | `blur` | `post.Blur` | 半径 0 走快速路径：整图拷贝 |

记画幅像素数 `N = W·H`，超采样率 `s = cfg.Supersample`（默认 2），
场景顶点总数 `V`（本测试场景为 1 个四边形，`V = 4`，与画幅无关），
blur 半径 `r = cfg.Blur`（默认 0）。

## 2. 预测模型 v1：按像素操作数计数（等权模型）

先只数"操作次数"，假设每次像素操作代价相同（权重均为 1）：

```
C_transform = V                          // 每个顶点一次仿射变换，与 N 无关
C_raster    = N · s²                     // 每像素 s² 个采样点，各做一次 Inside 判定
C_shading   = N                          // 每像素一次条件判断 + 至多一次写入
C_gamma     = N + 256                    // 每像素一次查表；另建 256 项 LUT（与 N 无关，先记着）
C_blur      = N · (2r+1)²   (r > 0)      // 一般情形：每像素 (2r+1)² 次邻域读
            = N             (r = 0)      // 快速路径：整图一次拷贝，按 N 次写计
```

默认配置 `s = 2, r = 0`，每帧像素操作总量：

```
C_total = V + 4N + N + N + N = V + 7N
预测占比 p_i = C_i / C_total
```

代入 `V = 4`（相对 N 可忽略，预测占比记为 ≈0）：

| 阶段 | 预测操作数 | 预测占比公式 | 数值 |
|---|---|---|---|
| transform | `V = 4` | `V/(V+7N)` | ≈ 0.00% |
| rasterize | `4N` | `4/7` | 57.14% |
| shading | `N` | `1/7` | 14.29% |
| gamma | `N`（忽略 +256） | `1/7` | 14.29% |
| blur | `N` | `1/7` | 14.29% |

两档画幅代入同一公式：`N₆₄ = 4096`，`N₂₅₆ = 65536`，预测占比完全相同（所有主项都正比于 N）。

## 3. 实测方法

- 计时点：`pipe/timing` 包，构建标签 `-tags vecgotiming` 时用 `time.Since`
  累计各阶段挂钟时长；默认构建为空函数，编译期内联消除，**输出 PGM 与原版逐字节一致**
  （已用 `cmp` 对 git HEAD 原版二进制验证）。
- 驱动：`go run -tags vecgotiming ./cmd/vecgobench 1000`，每档画幅先预热 10 帧再测 1000 帧取累计。
- 场景与 `cmd/main.go` 相同：单四边形；配置取 `config.Default()`（s=2, flat, gamma=1, blur=0）。
- 机器：linux/amd64，Go 1.26.8。

## 4. 预测 vs 实测对照（两档分行，阶段按执行顺序）

相对偏差 = (实测占比 − 预测占比) / 预测占比；阈值 ±20%。

## 5. 偏差落到具体阶段：v1 模型漏掉了什么

v1 的根本缺陷是"等权"——把一次浮点几何判定和一次字节查表当成同价操作。
另外它把每帧固定开销（与 N 无关的部分）也忽略了。逐阶段说明：

### rasterize：模型漏掉每次采样的实际单价（主导项）
模型只数了 `N·s² = 4N` 次操作，但每次操作不是一次简单访存，而是
`geom.Inside` 对 4 条边逐条做浮点比较、减法、除法 `(py-ay)/(by-ay)` 与叉积判断，
外加采样坐标 `px/py` 的浮点构造。实测每像素 41.3 ns（两档画幅一致：41.26/41.29 ns，
证明该阶段确实是纯 `N·s²` 计算、无固定项），而 shading 每像素仅 0.52–0.59 ns，
**单次 rasterize 采样的真实代价比一次像素读改写高约两个数量级**。
等权模型把它低估，导致 rasterize 占比被严重低估（预测 57% → 实测 96–97%）。

### shading：模型漏掉分支可预测性与无写入路径
`shading.Apply` 每像素只有一次 `if Pix[...] != 0` 判断，flat 模式下行值 `v`
在进入内层循环前就算好；且本场景只有多边形覆盖的像素发生写入。
模型按 N 次"完整操作"计数，实际是 N 次**可预测分支 + 少量写入**，单价远低于几何采样。
实测每像素 0.59 ns（64）→ 0.52 ns（256），大画幅下循环固定开销进一步摊薄。

### gamma：模型漏掉 256 项 LUT 的每帧固定构建成本
`post.Gamma` 每帧先调用 256 次自定义 `pow`（含乘幂迭代循环）建表，这部分与 N 无关，
v1 虽然在公式里写了 `+256` 却按等权处理、实质忽略。实测数据可直接拆出固定项：
设单帧耗时 `T_gamma = F + c·N`，用两档画幅联立：

```
F = (256·2442.5 − 64²·24670.3/64² ... )  用两点式：
c = (24670.3 − 2442.5) / (65536 − 4096) ≈ 0.362 ns/像素
F = 2442.5 − 0.362·4096 ≈ 961 ns/帧
```

即 LUT 构建约占 gamma 阶段耗时的 **39%（64×64）**，到 256×256 仅占 4%。
这解释了 gamma 每像素成本为何随画幅增大从 0.596 ns 降到 0.376 ns（−37%）：
固定项被更多像素摊薄。v1 预测占比不随画幅变化，与该现象直接矛盾。

### blur：模型漏掉 r=0 快速路径的固定分配成本
默认 `Blur(0)` 不做任何邻域计算，只 `raster.New` 分配一张 N 字节新图再 `copy`。
v1 按 N 次写计数，但漏掉了**每帧一次的堆分配固定成本**。同样两点式拆分：

```
c = (19146.2 − 2176.6) / (65536 − 4096) ≈ 0.276 ns/像素
F = 2176.6 − 0.276·4096 ≈ 1046 ns/帧
```

固定分配约占 blur 阶段 **48%（64×64）**、5%（256×256），每像素成本从 0.531 ns
降到 0.292 ns（−45%）。若改测 `r ≥ 1`，操作数公式应换回 `N·(2r+1)²`，
届时本阶段占比会按平方级上升——v1 公式对 r>0 的结构是对的，只是默认配置走了它没建模的快速路径。

### transform：偏差不显著，不触发 20% 规则
操作数 `V = 4` 与画幅无关，预测占比本身趋近 0；实测 0.02–0.08%，
绝对差在百纳秒级，低于计时噪声，按规则不做偏差归因。

## 6. 修正模型 v2：按操作类型加权 + 显式固定项

用 64×64 的实测每像素成本标定权重（令 1 权重单位 ≈ 0.59 ns，即一次 shading 像素操作），
再对 256×256 做**样本外**检验：

```
C_transform = V·w_v                     w_v ≈ 36 ns/顶点（含 make 分配，实测噪声大）
C_raster    = N·s²·w_r                  w_r ≈ 10.3 ns/采样  (= 41.26/4 次采样的每采样单价)
C_shading   = N·w_s                     w_s ≈ 0.59 ns/像素
C_gamma     = N·w_g + F_g               w_g ≈ 0.36 ns/像素, F_g ≈ 961 ns/帧（256 次 pow 建表）
C_blur      = N·w_b + F_b   (r = 0)     w_b ≈ 0.28 ns/像素, F_b ≈ 1046 ns/帧（新图分配）
            = N·(2r+1)²·w_b' (r > 0)
p_i = C_i / ΣC_j
```

权重含义可由指令结构复核：`w_r` 高是因为每次采样含 4 边 × 多条浮点指令（含一次除法），
`w_g/w_b` 低是因为只剩字节查表/顺序拷贝（缓存友好、无分支），`F_g/F_b` 是与 N 无关的每帧固定项。

v2 对 256×256 的样本外预测（直接代入上表权重，不重新拟合）：

| 阶段 | v2 预测占比 | 实测占比 | 相对偏差 |
|---|---|---|---|
| rasterize | 97.03% | 97.19% | −0.2% |
| shading | 1.39% | 1.22% | +13.9% |
| gamma | 0.89% | 0.89% | −0.5% |
| blur | 0.69% | 0.69% | −0.5% |

四个可归因阶段全部落入 ±20% 以内。残余偏差方向与机制一致：shading 仍偏高，
因为固定的行级循环开销在大画幅上继续摊薄（v2 未对 shading 再设固定项）。

## 7. 复现实验

```bash
# 实测（计时开启）
go run -tags vecgotiming ./cmd/vecgobench 1000

# 计时关闭：默认构建，无 vecgotiming 标签，计时调用内联为空函数
go build ./...
go test ./...

# 字节一致性回归（已验证）：原版 HEAD 与当前 off/on 三种构建输出 PGM 互相 cmp 相同
```
