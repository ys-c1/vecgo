# 半像素规则（Half-Pixel Rule）

本文定下贴边像素的归属规则，解决“同一场景两个平台差一行”的问题。规则只有两处选择，
实现与本文档必须保持一致。

## 1. 两处选择

| 选择项 | 约定 |
| --- | --- |
| **采样点取中心还是角点** | **取中心**。像素 `(col,row)` 的采样点是其几何中心；超采样时每个子像素同样取子像素中心。 |
| **边界算内还是算外** | **左上角规则（top-left rule）**。采样点恰好落在多边形边上时，只有**顶边**和**左边**算内，**底边**和**右边**算外。 |

采样坐标沿用本库的屏幕式约定：`px` 向右增大，`py` 随扫描行向下增大。

### 1.1 采样点公式（与 `raster.FillRule` 一致）

设多边形包围盒为 `[minx,maxx] × [miny,maxy]`，画幅 `W × H`，超采样因子 `ss`：

```
px = minx + (col + (si + 0.5)/ss) * (maxx-minx) / W
py = miny + (row + (sj + 0.5)/ss) * (maxy-miny) / H
```

其中 `si,sj ∈ [0,ss)`。注意 `0.5`：这就是“采样点取中心”。

### 1.2 边的分类（边界算内/算外）

对有向边 `a → b`，先按带符号面积判断绕向（面积正记为 CCW）：

| 边类型 | 几何判据（CCW） | 几何判据（CW） | 归属 |
| --- | --- | --- | --- |
| 顶边 | 水平 `dy=0` 且 `dx>0` | 水平且 `dx<0` | **算内** |
| 底边 | 水平 `dy=0` 且 `dx<0` | 水平且 `dx>0` | 算外 |
| 左边 | 非水平且 `dy<0` | 非水平且 `dy>0` | **算内** |
| 右边 | 非水平且 `dy>0` | 非水平且 `dy<0` | 算外 |

- 一个采样点若落在**顶点**上（同时贴两条边），采用 **OR 语义**：只要其中一条是顶边或左边就算内。
  因此结果与边的遍历顺序、多边形绕向都无关（见 `geom.TestWindingIndependence`、`TestTopLeftSquareCorners`）。
- 不落在任何边上的点，按射线法判严格内部。

### 1.3 矩形四角的归属真值表

| 角（屏幕视觉） | 相邻边 | 左上角规则 |
| --- | --- | --- |
| 左上 | 顶边 + 左边 | 算内 |
| 右上 | 顶边 + 右边 | 算内（顶边命中，OR） |
| 右下 | 右边 + 底边 | 算外 |
| 左下 | 底边 + 左边 | 算内（左边命中，OR） |

这样任意两个共享一条边的多边形，共享边上的像素只归属其中一侧：既不漏也不重复。

## 2. 旧规则保留为可选参数，不是编译开关

旧的 `geom.Inside` 射线法没有明文边界约定：贴边点是否算内，取决于射线法里
`(ay>py)==(by>py)` 的奇偶比较和浮点除法是否恰好落在边上——等价于“顶边/右边算内”的
偶然结果，且对浮点实现敏感（跨平台差一行的根因之一）。

旧规则原样保留，通过**运行时参数**切换：

- 配置字段：`config.Config.EdgeRule`，取值 `"half-pixel"`（默认）或 `"legacy"`；
- 解析函数：`config.ParseEdgeRule`；
- 渲染入口：`raster.Image.FillRule(polys, ss, rule)`，无参 `Fill` 等价于 `FillRule(..., RuleHalfPixel)`；
- 命令行：`vecgo -rule half-pixel out.pgm`（默认）或 `vecgo -rule legacy out.pgm`。

`RuleLegacy` 直接调用历史 `Inside`，因此切回旧规则的产物与改动前**逐字节一致**
（见 `pipe.TestLegacyByteIdentical`，对 9 个场景的 PGM 做字节比对）。

## 3. 统一后的覆盖像素数（具体数字）

阈值固定为 `CountOn(128)`。下表为经完整管线（含 `pipe.Transform`）渲染的结果，
旧/新并列，差值单列。黄金文件在 `pipe/testdata/{legacy,half}-S*.pgm`。

| 场景 | 几何 | 画幅/ss | 旧 on | 新 on | 差值（新−旧） | 变化像素数 |
| --- | --- | --- | --- | --- | --- | --- |
| S1 | 默认正方形 | 64² / ss2 | 4096 | 4096 | 0 | 0 |
| S2 | 三角形 | 16² / ss1 | 120 | 120 | 0 | 0 |
| S3 | 另一朝向三角形 | 16² / ss1 | 136 | 136 | 0 | 0 |
| S4 | S2 的 ss2 | 16² / ss2 | 136 | 136 | 0 | 0 |
| S5 | 两块相邻矩形 | 16² / ss1 | 256 | 256 | 0 | 0 |
| S6 | 铺满画幅矩形 | 16² / ss1 | 256 | 256 | 0 | 0 |
| **S7** | **退化三角形（共线顶点）** | 16² / ss1 | **0** | **16** | **+16** | **16** |
| S8 | 非退化直角三角对照 | 16² / ss1 | 120 | 120 | 0 | 0 |
| S9 | 非退化斜三角对照 | 16² / ss1 | 136 | 136 | 0 | 0 |

### 3.1 关键结论

1. **所有非退化场景（S1–S6、S8、S9）两规则逐像素相同，差值为 0。**
   在“中心采样 + 边落在半整数网格”的常规配置下，采样点不会精确贴边，规则差异不被触发。
2. **唯一可复现的差异是 S7 这类退化几何**：三角形 `(0,0),(16,16),(8.5,8.5)` 有两个顶点与
   对角线共线（零面积），斜边恰好穿过 16 个采样中心。旧射线法在整条贴边斜边上逐点判外，
   覆盖 **0**；左上角规则按左边归属恢复这些点，覆盖 **16**，差值 **+16**。
3. 退化几何正是历史上最容易跨平台不一致的输入：贴边判定依赖浮点相等性，不同平台的
   浮点实现会让结果在 0 和 16 之间摆动。明文规则把它固定为确定的 16。

## 4. 为什么会“差一行”：浮点微扰

纯填充层（`raster.FillRule`，坐标即采样坐标）与完整管线（`pipe.Run`，先做 `Transform`）
在 S4 上给出不同覆盖：

| 层 | S4 覆盖（两规则相同） |
| --- | --- |
| 纯填充层 `raster` | 120 |
| 完整管线 `pipe`（含 `Transform`） | 136 |

`Transform` 即使在 `rotate=0` 时也会做 `cos(0)/sin(0)` 浮点运算，把本来恰好贴边的顶点
挪动一个极小量，使贴边采样点落到严格内部或严格外部。旧规则对这种挪动没有确定性约定，
不同平台/编译器的浮点细节不同，就表现为“差一行”。左上角规则把贴边归属写成明文的
拓扑判据（顶/左算内，底/右算外），不再依赖浮点相等性，从而消除该分歧。

## 5. 验证方式

- `geom`：四角真值表、边中点、绕向无关、`RuleLegacy` 与历史 `Inside` 等价。
- `raster`：九场景两规则覆盖数、S7 差值 +16 且仅 16 像素变化、非退化场景逐像素不变、
  `Fill` 默认半像素规则。
- `pipe`：经完整管线渲染，`legacy` 与冻结基线 9 个 PGM **逐字节一致**，
  `half-pixel` 与黄金文件逐字节一致，覆盖数符合第 3 节数字。
