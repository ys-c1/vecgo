# 边界翻转规则（Boundary Flip Rule）

同一条边，从两个方向遍历时，扫描线奇偶位不同，填出的像素就不同。本文把
补翻转的触发条件写成明文规则，给出面积守恒的推导，并用整数格点验证。

## 1. 问题：方向依赖从哪来

实现在 `scan` 包。约定：

- 单元 `(col,row)` 覆盖 `[col,col+1]×[row,row+1]`，采样点取单元中心
  `(col+1/2, row+1/2)`；
- 坐标放大两倍后全部是整数：顶点落在偶格点 `(2x,2y)`，采样中心落在奇格点
  `(2col+1, 2row+1)`。采样中心是奇数、顶点是偶数，所以**采样点永远不会落在
  顶点上**，退化只剩“采样点落在边的内部”一种；
- 奇偶规则：每条边对采样点贡献一位，所有位异或，结果为 1 即在多边形内。

对一条边 `a→b`，射线法只看它是否跨越 `py`，交点在 `px` 右侧就翻一位。
采样点恰好落在边上时（`lhs == 0`），交点就是采样点本身，“右侧”没有定义。
实现必须替这条边指定一个固定的归属。默认写法是

```
b(a→b) = [dy > 0]
```

即**向上**穿越的边在贴边时把位翻成 1，向下翻成 0。这个基准位带着方向：
同一条边掉头后 `dy` 取反，`b(b→a) = 1 − b(a→b)`。于是一条恰好压着若干
采样中心的边，正向遍历时给它们比特 1，反向遍历时给 0——两条路径的并集
的像素数就不同了。

## 2. 补翻转的触发条件（两行推导）

```
基准位        b(a→b) = [dy > 0]
补翻转        b*(a→b) = b(a→b) ⊕ [a ≻ b]，  ≻ 为 (x,y) 字典序
```

两行依据：

1. **不变性**：掉头把 `(a,b)` 换成 `(b,a)`，`[dy>0]` 取反，`[a≻b]` 也取反，
   二者异或的结果不变，故 `b*(a→b) = b*(b→a)`；基准位与遍历方向有关，
   按字典序补的翻转恰好把这份依赖消掉。
2. **完备性**：`a ≠ b` 时两个布尔量必有一个为真，`⊕` 永远只落在相异
   结果上；两端点字典序相等当且仅当 `a = b`，此时 `dy = 0`，该边不跨越
   `py`，根本不会进入贴边分支，补翻转不需要触发。

## 3. 何时需要补一次翻转

| 情形 | `a ≻ b` | 是否需要补 | 理由 |
| --- | --- | --- | --- |
| 存储方向已是字典序（起点更小） | 否 | 不补 | 基准位已是规范归属 |
| 存储方向逆字典序（起点更大） | 是 | **补一次** | 掉头使基准位取反，补回规范归属 |
| 边不跨越扫描线（含水平边） | 任意 | 不补（也不会触发） | `bitAt` 在跨越判断处提前返回 0 |
| 采样点不贴边（`lhs ≠ 0`） | 任意 | 不补 | 补翻转只在 `lhs == 0` 分支读取 |

**触发点只有一处**：`scan.Edge.bitAt` 中 `lhs == 0` 的分支——

```go
if lhs == 0 {
    var b uint8
    if dy > 0 { b = 1 }
    if correct && e.Flip { b ^= 1 }   // ← 补翻转只在这里发生
    return b
}
```

`e.Flip` 在 `scan.Edges` 构造有向边时按 `greater(a, b)` 一次算好，运行时
只读不改。补翻转因此是**每条边一次的静态标注**，不是每像素的动态判断，
也不改变非贴边像素。

## 4. 面积守恒的推导

设正向遍历得到覆盖集 `F`，反向得到 `R`。两套遍历用的是同一组无向边，
只是每条边掉头；贴边分支上的补翻转使 `b*` 与方向无关，所以任意采样点上
正反两次的异或值逐位相同：

```
∀p:  parity_F(p) = parity_R(p)   ⇒   F = R   ⇒   |F| = |R|
```

每个单元面积恰为 1，`|F|` 就是填充面积。于是**面积差 `|F| − |R| = 0`**，
而且是整数意义上的 0（见第 6 节）。

不补翻转时，设贴边采样点集合为 `T`，其中边在词典序下“逆序”的贴边点
集合为 `T≻`。两个方向在这些点上取值相反，其余点相同，故

```
|F| − |R| = Σ_{p∈T≻} ±1   （符号由该点的奇偶累积决定）
```

差值一般不为零，除非 `T≻` 恰好成对抵消。这正是“同一条边两个方向像素数
不同”的量。

## 5. 三类多边形各验一次

格点画幅 `8×8`，采样中心 `(col+1/2,row+1/2)`。`补翻转后` 一栏正、反两个
方向数字必须相等；`不补翻转` 一栏是同一几何省掉补翻转的对照，用来证明
补翻转确有必要。

| 类别 | 几何（正向顶点序） | 2A | 补翻转后 正向 / 反向 | 不补翻转 正向 / 反向 | 差值 | 差异贴边 |
| --- | --- | --- | --- | --- | --- | --- |
| 凸多边形 | `(0,0) (7,0) (0,7)` | 49 | **21 / 21** | 28 / 21 | +7 | 边 1（斜边） |
| 凹多边形 | `(0,0) (8,0) (8,8) (4,4) (0,8)` | 96 | **44 / 44** | 52 / 44 | +8 | 边 2、边 3（缺口两斜边） |
| 自交多边形 | `(0,0) (8,8) (0,8) (8,0)` | 0 | **32 / 32** | 32 / 32（像素不同） | 0 | 边 0、边 2（两条交叉边） |

- **凸**：斜边 `(7,0)→(0,7)` 穿过 7 个采样中心，不补翻转时正向多算 7 格。
- **凹**：箭头的缺口由边 2、边 3 夹成，同一扫描行上有两个贴边点，两处
  都只在正向被计入，缺口 8 格。
- **自交**：领结的两条交叉边贴边点正反相反、互相抵消，**覆盖数相同
  （32/32）但掩码不同**——有 16 个单元的覆盖位翻转。这是“数目对、位置错”
  的情形，恰好说明只比总数不够，必须逐像素比。

### 5.1 不满足条件的样例：差在哪条边

反例取等腰直角三角形 `(0,0) (5,0) (0,5)`——只有一条斜边，贴边采样点
无法两两抵消：

- 不补翻转：正向 **15**，反向 **10**，差 **+5**；
- 5 个差异单元的采样中心全部贴在**边 1**，即斜边 `(5,0)→(0,5)`，
  坐标是 `(4,0) (3,1) (2,2) (1,3) (0,4)`；
- 补翻转后正反均为 **10 / 10**，差异 0。

`scan.Diagnose` 会把每个差异单元连同命中边的下标一起返回，测试
`TestBrokenCasePointsToEdge` 断言上表数字与“只落在边 1”两点。

## 6. 面积差为零：用整数格点，不用浮点近似

两条独立证据，全程没有浮点：

1. **覆盖计数**：`Mask.Count()` 返回 `int`，`int64(fwd.Count()) - int64(rev.Count())`
   严格等于 `0`，不是 `|x| < ε`。测试 `TestThreeClassesEqualCounts`。
2. **鞋带公式**：`scan.Area2` 用 `int64` 逐项累加 `x0*y1 − x1*y0`，
   `Area2(poly) + Area2(reverse(poly)) == 0` 逐位成立。测试
   `TestAreaDifferenceIsInteger`；三类多边形的 `2A` 分别是 `49 / 96 / 0`。

输入校验也拦住浮点来源：顶点坐标必须是整数（`p.X != math.Trunc(p.X)` 即报错），
坐标上限 `±2^20`、画幅上限 `8192`，保证两倍坐标与交叉相乘不会溢出 `int64`。

## 7. 一个容易混淆的点

仓库现有 `raster.Fill` 用**逐像素解析式射线法**（`geom.Inside`），它对
每个像素独立判定，正反遍历天然一致——上面的方向依赖不会在那里出现。
方向依赖发生在**扫描线按边累积奇偶**的写法里，`scan` 包按这种写法实现，
因为只有那里才存在“这条边在我掉头之后还算不算贴边”的选择。换句话说，
补翻转是扫描线填充器的边界约定，不是几何库的全局属性。

## 8. 验证方式

```
go test ./scan -v
```

测试覆盖：

- 三类多边形正反覆盖数、逐像素掩码、面积差为 0；
- `Area2` 正反互为相反数，和为整数 0；
- 不补翻转时三类都出方向依赖，差异只落在贴边单元，且归到上表所列的边；
- 反例 15/10、差 5、全在边 1，补翻转后 10/10；
- 顶点序循环移位不改变结果（另 `TestEdgeFlipFlag` 核对 `Flip` 的构造）；
- 无贴边采样点的几何在补翻转前后逐像素相同（补翻转不外溢）。
