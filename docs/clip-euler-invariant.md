# 裁剪的欧拉不变量

本文把“裁剪前后顶点、边、面片数量对不上”这件事定成一个可检验的不变量：
先写出公式，再按 Sutherland–Hodgman（下称 SH）的每一步说明哪些顶点会被
合并、哪些边会退化，最后给出三类裁剪框的实测量。

实现见 `geom/topology.go`（计数与清理）、`geom/clip_report.go`（诊断）。
可复现报告：`go run ./cmd/clipinvariant`。

## 1. 不变量

对裁剪结果这个闭合环，记

| 量 | 定义 |
| --- | --- |
| **V** | 环上顶点表的长度。重复坐标按出现次数计——SH 的每次“顶点事件”都算一次，这正是顶点数虚增的来源。 |
| **E** | 不同无向边的条数。零长边（两端点相同）不计；同一条边无论走几次只计一次。 |
| **F** | 平面图的 face 数 = 1 个无界面 + 有界面数。零面积环只有无界面。 |

不变量：

```
V − E + F = 2        （χ = 2）
```

`F` 的取法：

- 非零面积、无自接触：`F = 2`；
- 有捏点（非相邻顶点重合）：按捏点把走线拆成带回路的段，`F = 1 + 有界回路数`；
- 有真自交：每个交叉点额外贡献 1 个有界面，`F = 1 + 回路数 + 交叉数`；
- 单点环 `V=1,E=0,F=1`；线段环 `V=2,E=1,F=1`；空环 `V=0`（不变量不适用）。

### 1.1 这条不变量“查得出什么、查不出什么”

这是本文最重要的一段，因为它决定了只看 χ 会漏报。

| 退化类型 | 对 V、E、F 的影响 | χ 是否变化 | 能否只靠 χ 发现 |
| --- | --- | --- | --- |
| 相邻重复顶点 | V+1，E 不变（零长边不计），F 不变 | +1 | **能** |
| 单点环（n 个顶点重合） | V=n，E=0，F=1 | n−1 | **能** |
| 共线中间顶点 | V+1，E+1，F 不变 | 0 | **不能** |
| 折返尖刺（a→b→a） | 视上下文，通常 V+2、E+1 | 可能为 0 | **不能**，需逐点判 |
| T 型接触（顶点落在非相邻边上） | V、E 不变，F 不变 | 0 | **不能** |
| 非相邻边共线重叠 | V、E 不变，F 不变 | 0 | **不能** |

结论：**χ=2 是必要条件，不是充分条件**。实现里因此把不变量拆成三层一起报：

1. `EulerCounts`：V、E、F、χ、Δ，以及 `Crossings`/`Repeated`/`TJunctions`/`Overlaps` 四个接触计数；
2. `CleanResult.Removed`：清理时被合并/删除的每个顶点，带类别；
3. `CleanResult.Residual`：清理后仍无法靠“合并相邻顶点”消除的退化。

`CheckInvariant` 只在三层同时干净时放行；否则 `*InvariantError` 报出
**差几个（Δ）、差在哪一类、前 5 个坐标**。

## 2. 按 SH 算法逐条推导

SH 对窗口的每条边依次执行“保留内侧点、在跨越处插入交点”。每条窗口边
一遍遍历 `out`，按 `(prv, cur)` 的进出状态输出 0~2 个点：

| 状态 | 输出 | 产生的退化 |
| --- | --- | --- |
| 内→内 | `cur` | 无 |
| 外→内 | `交点`, `cur` | 若 `cur` 恰在窗口边上，交点与 `cur` 重合 → **相邻重复** |
| 内→外 | `交点` | 若 `prv` 在窗口边上，交点与刚输出的 `prv` 重合 → **相邻重复** |
| 外→外 | 无 | 若边与窗口边共线掠过，可产生零长输出 → 后续成为**零面积段** |

由此可推出三类必然出现的退化：

1. **顶点恰落在窗口边上**：`inside()` 用 `>= 0`，顶点被同时判为“在边上”。
   若窗口边与主体边共线，该顶点会先作为 `cur` 输出一次、再作为交点输出一次，
   形成相邻重复点。此时 **V 多 1，E 不变，χ 变 +1**——这就是“顶点数对不上”的直接来源。
2. **主体与窗口只是相切（点/线段接触）**：所有输出点重合或共线，
   得到单点环或线段环，`V` 远大于 1 而 `E≈0`，χ 偏离 2。
3. **共线中间顶点**：若主体本身在窗口某条边上有共线点（输入就带冗余），
   SH 会原样保留。此时 `V=E` 同时增加，**χ 仍为 2，但顶点数已被虚增**。

### 2.1 哪些顶点会被合并、哪些边会退化

实现按以下顺序清理，且合并成**单次不动点循环**（删掉一个点后新形成的
相邻三点必须重新检查，否则会漏掉二次重复）：

1. **相邻重复顶点**（含首尾相接）→ 合并，记 `KindDuplicate`。
   零长边随之消失，`E` 不变而 `V` 减一，χ 回落到 2。
2. **共线中间顶点**（`b` 落在 `a—c` 之间且在直线上）→ 删除，记 `KindCollinear`。
   `V`、`E` 各减一，χ 不变。
3. **折返尖刺**（`a、b、c` 共线但 `b` 不在 `a、c` 之间）→ 删除，记 `KindSpike`。
   这是 a→b 原路退回，不围任何面积；只删“中间点”的实现会漏掉它。
4. **零面积环** → 收缩为相距最远的两点（线段）或一点，其余记 `KindZeroArea`。

清理后仍存在的下列退化**不属于“合并相邻顶点”能解决的范围**，进入 `Residual`：

- 空环（`KindEmpty`）、单点环（`KindPointRing`）、线段环（`KindSegmentRing`）；
- 捏点（`KindPinch`，非相邻顶点重合）；
- 真自交（`KindSelfCross`）；
- T 型接触（`KindTJunction`，顶点落在非相邻边上）；
- 非相邻边共线重叠（`KindOverlapEdge`）。

### 2.2 凹主体的前提

SH 只对**凸**主体保证得到简单环。凹主体在凹角处会被裁成带桥接的环，
出现捏点与 T 型接触——这正是扫描里 100% 的“违反不变量”来源。
`geom.IsConvex` 用来把这类前提违例与真正的清理缺陷区分开：凹主体被
`CheckInvariant` 明确报出（不会静默通过），但不会被误判成“清理算法有 bug”。

## 3. 三类裁剪框的实测

主体：`(0,0),(10,0),(10,10),(0,10)` 正方形（凸，有向面积 100）。
三类框定义：

- **A 包含型**：窗口完整包住主体，不切边；
- **B 穿透型**：窗口边逐条切过主体，每条被切边产生一个交点；
- **C 贴边退化型**：窗口边与主体边共线、顶点落在窗口边上或只触到一角。

`go run ./cmd/clipinvariant` 的实测（节选）：

| 类 | 框 | 前 V/E/F/χ | SH 原始流 V/E/F/χ | 清理后 V/E/F/χ | ΔV | ΔE | 退化顶点数 | 类别 | 坐标(≤5) |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| A | 全包 | 4/4/2/2 | 4/4/2/2 | 4/4/2/2 | 0 | 0 | 0 | — | 无 |
| A | 等大 | 4/4/2/2 | 4/4/2/2 | 4/4/2/2 | 0 | 0 | 0 | — | 无 |
| B | 菱形切角 | 4/4/2/2 | 8/8/2/2 | 8/8/2/2 | +4 | +4 | 0 | — | 无 |
| B | 切三条边 | 4/4/2/2 | 4/4/2/2 | 4/4/2/2 | 0 | 0 | 0 | — | 无 |
| B | 斜三角窗 | 4/4/2/2 | 4/4/2/2 | 4/4/2/2 | 0 | 0 | 0 | — | 无 |
| C | 边共线 | 4/4/2/2 | **5/4/2/3** | 4/4/2/2 | 0 | 0 | 1 | 相邻重复×1 | (10,0) |
| C | 只触一角 | 4/4/2/2 | **4/0/1/5** | **1/0/1/2** | −3 | −4 | 3 | 相邻重复×3 | (10,10)×3 |
| C | 触整条边 | 4/4/2/2 | **4/1/1/4** | **2/1/1/2** | −2 | −3 | 2 | 相邻重复×2 | (10,0),(10,10) |
| C | 顶点落边 | 4/4/2/2 | 4/4/2/2 | 4/4/2/2 | 0 | 0 | 0 | — | 无 |

读法：

- **A 类**：裁剪不切边，V/E 不变，无退化。
- **B 类**：只有“菱形切角”真正切穿了四条边，每条边产生一个交点，
  所以 V、E 各 +4，`ΔV=ΔE=+4`，χ 仍为 2，无退化。另两个 B 框窗口边恰好
  沿主体边/顶点走，不产生交点，数值不变。
- **C 类**：SH 原始流全部 **χ≠2**，正是“顶点数对不上”的证据：
  - 边共线：原始流 V=5、E=4，χ=3。多出的 1 个顶点是 `(10,0)` 的重复；
  - 只触一角：原始流 4 个点全重合，E=0、χ=5。清理后收缩成单点环，
    V=1、χ=2——**χ 满足但无面积**，必须靠 `HasArea()` 判定；
  - 触整条边：原始流 4 个点构成一条线段（两个坐标各重复一次），
    χ=4。清理后 V=2、E=1、χ=2，同样无面积。

**边数变化的完整报告**：C 类清理不仅减少顶点，也减少边——
`ΔE` 分别为 0、−4、−3，而 A/B 类的 `ΔE` 与 `ΔV` 同步（B1 为 +4，其余为 0）。
只报顶点数会漏掉这一半信息。

### 3.1 不变量结论

- 9 个框清理后**全部满足 V−E+F=2**（B1 与 C2/C3 的“无面积”情形由
  `HasArea()` 单独标注，不混同于“有效面”）；
- 违反不变量的只有 C 类的 **SH 原始流**，差值分别为 +1、+3、+2，类别全部是
  **相邻重复顶点**——即“退化顶点没清掉”的猜想成立，但只发生在
  **清理前**；清理后的结果自洽。

## 4. 已知边界（扫描发现，已用测试钉住）

对凸主体做 3 类窗口 × 网格扫描（`TestConvexSweepAllSatisfy`）：**0 违反**。
对凹主体（`notch`、`concave`）扫描：存在违反，全部由 `KindTJunction` /
`KindPinch` / `KindOverlapEdge` 报出，来自 SH 在凹角处的桥接，属于算法前提
违例，不是清理缺陷（`TestConcaveSubjectIsReportedNotSilent`）。

补充：输入多边形自身带重复点或共线点时，`ClipRaw` 会原样带入；
`Clip` 会在清理阶段一并去掉（`TestCleanupReachesFixpoint`）。

## 5. 复现

```sh
go test ./geom -run 'Invariant|ThreeClasses|RawClip|Fixpoint|Spike|Collinear|EmptyRing|ConvexSweep|Concave|CoordsCap' -v
go run ./cmd/clipinvariant          # 打印上表全部数值
go run ./cmd/clipinvariant -fail    # 不变量不成立时退出码 1（当前应为 0）
```
