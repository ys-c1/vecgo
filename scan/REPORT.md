# 凸多边形逐行填充：端点单调增量改造

代码：`scan.go`（算法）、`shapes.go`（三组形状与反例）、`scan_test.go`（等价性/计数/基准）、
`../cmd/scanlab/main.go`（一键输出全部数据）。

复现：

```bash
go test ./scan/...                      # 等价性、反例、计数测试
go run ./cmd/scanlab                    # 本文所有表格与字符反例
go test ./scan -run='^$' -bench=. -benchmem
```

行坐标约定：第 `r` 行扫描线取 `y_r = r + 1/2`（像素中心），第 `c` 列中心 `c+1/2`
落入闭区间 `[XL, XR]` 即点亮。三组代表形状顶点都是整数坐标，半整数扫描线不经过顶点，
没有交点二义性。

## 1. 单调性证明（先把“单调”的准确含义说清楚）

设凸多边形 `P`，最低点顶点记 `B`（y 最大）、最高点记 `T`（y 最小）。

1. **凸集的水平截面是区间。** 对任意 y，`P ∩ {Y=y}` 是凸集与直线的交，必为一条线段
   `[L(y), R(y)]`；当扫描线不经过顶点时，边界与该线恰好有两个交点。
2. **两条边界弧都是 y-单调链。** 多边形边界被 `T、B` 分成 `T→B` 的两条弧。若某条弧在
   自上而下的过程中出现严格的 y 回折（一个局部 y 极值），取刚好越过该极值的一条水平线，
   它会与同一条弧相交至少两次、再与另一条弧相交至少一次，合计 ≥3 个交点，与“凸截面只有
   两个边界交点”矛盾。故每条弧上的顶点 y 单调不减，**活动边的下标只会单向前进，不会回退
   或重扫**。
3. **同一条边内，相邻两行的端点差是常数。** 这就是题目所说的“相邻两行端点随行号单调
   移动”：端点沿该边等差移动，增量符号在该边内不变。

> 严谨性提示：若把“单调”理解成 min/max 端点的 **x 坐标全局只朝一个方向**，凸性并不保证。
> 菱形 `(2,0),(4,2),(2,4),(0,2)` 的左端点序列是 `2 → 0 → 2`，先左后右。真正成立、且足够
> 支撑增量算法的是上面的 **y-单调链（边游标单向推进）+ 边内 Δ 恒定**；Δ 在换边处可以变号。
> 本文 C 组的 Δ 序列 `4,2,0.5,0.25,-0.25,…` 本身就演示了这种变号，算法靠第 3 节的越界换边
> 正确处理，而不是假设 Δ 永远同号。

非凸形状破坏的正是这两条：截面可能有 4 个以上交点（不再是单一区间），边界弧也可能 y 回折
（游标只前进会漏边）。反例见第 6 节。

## 2. 增量更新量（一行式子）

对定向为 `y1 < y2` 的边 `P1=(x1,y1), P2=(x2,y2)`，行距 h=1 时：

```text
Δx = x(r+1) − x(r) = (x2 − x1) / (y2 − y1)
```

一般行距 h 时右端再乘 h。于是每行端点只需 `x ← x + Δx` 一次加法，除法从“每行每交点一次”
降为“每条边建链时一次”。

## 3. 不会越界的证明 与 越界判定条件（一行）

边内第 k 次更新后：

```text
x_k = x1 + (y_r + k − y1)·(x2−x1)/(y2−y1)
    = (1−λ)x1 + λ x2,   λ = (y_r + k − y1)/(y2−y1)
```

只要下一行扫描线仍在边的 y 范围内（`y_r+k ≤ y2`），就有 `λ∈[0,1]`，所以 `x_k` 是 `x1,x2`
的凸组合，必有 `min(x1,x2) ≤ x_k ≤ max(x1,x2)`——**增量端点绝不会越出该边的 x 边界**。

代码中统一使用的越界（该换边）判定，一行：

```go
oob := y >= ch.yb // 当前扫描线到达/越过边的下端点 y2
```

对非竖直边，它等价于纯 x 的代数越界判定（也是一行）：

```text
(x′ − x1)(x′ − x2) > 0   // 乘积为正 ⇔ x′ 落在 [x1,x2] 之外
```

注意竖直边 `x1=x2` 时该乘积恒为 0、无法报越界（这是开发中实测发现并修正的坑，
有测试覆盖），所以实现采用对竖直边同样成立的 y 式。判定为越界后，凸性保证下一条边恰好从
`(x2,y2)` 开始，换边并用边方程重新定位一次即可；游标在到达最低点前不会越过链尾。
写帧缓冲前另有列裁剪 `lo<0→0; hi>=W→W−1`，保证内存不越界。

## 4. 三组形状：更新量与按行边界检查次数

画幅统一 `200×200`。第 r 行对两条链各评一次越界条件；换边行当新边再评一次。
**题目要求的“每组一个数”——按行统计后汇总的越界判定总次数——为：A=320，B=240，C=334。**

| 组 | 顶点数 | 覆盖行 | 两条链的 Δx 序列 | **边界检查总数** | 按行分布 |
|---|---:|---:|---|---:|---|
| A 三角形 `(100,20)(60,180)(140,180)` | 3 | 160 | `[-0.25]` / `[+0.25]` | **320** | 160 行各 2 次 |
| B 平行四边形 `(70,30)(170,30)(140,150)(40,150)` | 4 | 120 | `[-0.25]` / `[-0.25]` | **240** | 120 行各 2 次 |
| C 对称凸十六边形（坐标见 `cleanPolygon16`） | 16 | 160 | `[4,2,.5,.25,-.25,-.5,-2,-4]` / `[-4,-2,-.5,-.25,.25,.5,2,4]` | **334** | 153 行各 2 次，7 个换边行各 4 次 |

`334 = 160×2 + 14`：两条链各换边 7 次，每次换边对新边多评 1 次。原始逐行计数保存在
`Counts.PerRowOOB []int`（长度 H，每个元素就是该行的检查次数），并有
`TestBoundaryCheckCounts` 把 `320/240/334` 与行分布锁死。

工作量对比（同一次填充，实测计数）：

| 组 | 重算：边跨线检查 | 重算：端点除法 | 增量：`x+=Δ` | 增量：斜率除法 |
|---|---:|---:|---:|---:|
| A | 600（=3 边 × 全部 200 行） | 320 | 318 | 2 |
| B | 800 | 240 | 238 | 2 |
| C | 3200 | 320 | 318 | 16 |

基准实现即使在多边形外的空行也逐边检查；增量实现只遍历 y 范围内的行。

## 5. 逐像素等价性 与 耗时（本机实测）

正确性：`TestGroupsPixelIdentical` 对三组代表形状及 160 个语料凸型
（64 三角形 + 64 四边形 + 32 个 48 边形）要求两块缓冲 `bytes` 级相同，差异像素均为 **0**；
`TestRandomConvexDifferential` 另跑 4000 个随机点凸包差分，全部一致。代表形状端点到像素
中心判定线的最小距离为 0.125 像素，不存在平局；列换算里保留 `1e-9` 的平局容差，吸收除法与
Δ 累加之间约 1 ulp 的差异。

耗时（linux/amd64 / Go 1.26.8，`go test -bench -count=5` 的中位数；原始记录见
`../artifacts/bench.txt`、`../artifacts/scanlab-output.txt`）：

**只算逐行区间端点（本次优化的部分）**

| 组 | 逐行重算 ns/op | 增量 ns/op | 下降倍数 |
|---|---:|---:|---:|
| A 三角形 | 2027 | 1813 | **1.12×** |
| B 平行四边形 | 2366 | 1541 | **1.54×** |
| C 凸十六边形 | 7846 | 1805 | **4.35×** |

**端到端填充（区间 + 完全相同的写像素，缓冲复用）**

| 组 | 逐行重算 ns/帧 | 增量 ns/帧 | 下降倍数 |
|---|---:|---:|---:|
| A 三角形 | 6623 | 6445 | **1.03×** |
| B 平行四边形 | 10165 | 9311 | **1.09×** |
| C 凸十六边形 | 19915 | 14070 | **1.42×** |

三角形面积小、端点计算本来就只占整帧约 1/4，端到端被相同的像素写主导（Amdahl），所以只有
约 3%；边越多，`O(E·H)` 的逐边重扫越浪费，增量优势越大。复杂度从 `O(E·H)` 次跨线检查 +
每覆盖行 2 次除法，降为 `O(H+E)` 次加法/判定 + `O(E)` 次斜率除法；写像素成本两者相同。

## 6. 非凸反例：增量式什么时候会错

### 反例一：侧凹七边形 —— x 单调性被凹口破坏，“一次定 Δ、永远 x+=Δ”必错

顶点 `NotchPolygon()`：`(0,0)(8,0)(8,8)(0,8)(0,6)(3,4)(0,2)`。逐行重算得到的左端点序列
（行 0..7）：

```text
L_r = [0, 0, 0.75, 2.25, 2.25, 0.75, 0, 0]
```

先从 0 单调增到 2.25，又单调减回 0——方向反转。首行相交的左边是竖直边 `(0,0)-(0,2)`，
算得 `ΔL=0`；最简增量写法 `FixedDeltaWrong` 之后一直 `xL += 0`，于是把凹口全部填实。
与奇偶正确缓冲逐像素相比恰好误填 6 点：

```text
[[行2,列0] [3,0] [3,1] [4,0] [4,1] [5,0]]
```

字符画（`go run ./cmd/scanlab` 可看）：正确结果第 2–5 行左侧按 `.#######.` /
`..######.` 收进去，固定 Δ 写法 8 行全部填成 `########.`。

值得强调：这个凹形的边界弧在 **y 方向仍单调**，所以本文带越界换边的完整增量实现会在
`y>=y2` 时把 Δ 从 `0` 换成 `+1.5`、再换成 `−1.5`、再换回 `0`，结果仍与奇偶配对一致
（`TestNotchMonotonicityAndFixedDelta` 同时锁了这两点）。**真正杀死“固定 Δ 不换边”写法的
是 x 方向反转。**

### 反例二：悬挑凹多边形 —— 扫描线有 4 个交点，两链/单区间假设失效

`OverhangPolygon()`：`T(5,0), A(9,3), N(6,2), D(9,6), B(5,10), L2(2,7), L1(1,3)`。
右链上 `A(9,3)→N(6,2)` 的 y 从 3 退回 2（y 回折）。在第 2 行（y=2.5）上有 4 个交点：

```text
x = 1.667, 6.375, 7.5, 8.333
```

奇偶配对给出两个区间 `[1.667,6.375] ∪ [7.5,8.333]`（凹档 `(6.375,7.5)` 为空）；凸性增量法
与逐行 min/max 重算都只保留 `[1.667,8.333]`，把凹档填实。实测：增量法与 min/max 重算
**0 像素差异**（增量改造本身完全等价），但二者相对奇偶正确结果在该行第 6 列等位置共
**1 个像素错误**（小画布 12×11 上；`TestCounterexampleOverhang` 锁定错误点 `[2,6]`）。

**结论**：凸性保证“两交点、两 y-单调链”，增量换边严格正确且逐像素等价；一旦形状非凸，
要么 x 端点方向反转（固定 Δ 写法错），要么一条扫描线出现 ≥4 个交点 / 边界 y 回折
（两链单区间写法错）。非凸多边形应改用全交点 + 排序 + 奇偶配对（本包 `EvenOdd`）或完整的
活动边表。
